NVIDIA Dynamo 的会话感知智能体推理

依据：原文

来源：https://pytorch.org/blog/session-aware-agentic-inference-with-nvidia-dynamo/

智能体任务会反复调用模型，并在工具执行期间保留不断增长的上下文。文章介绍 NVIDIA Dynamo 如何用稳定的会话 ID 串联请求，让路由、调度和 KV 缓存管理利用整个会话的信息。

问题与会话标识

传统服务系统逐个请求决定路由和缓存，难以识别同一智能体后续还会复用的上下文。并发会话增多时，留在显存中的 KV 缓存可能超出容量，导致驱逐和重复预填充。Dynamo 将同一任务的请求归入 session_id，并用 parent_session_id 关联子智能体。它能直接识别 Claude Code、Codex 和 OpenCode 的会话头；自定义框架可发送 X-Dynamo-Session-ID。各项优化按需启用。

追踪与复现

启用 DYN_REQUEST_TRACE=1 后，Dynamo 记录会话、输出 token 数、结束原因、缓存指标、工具名称及用于复现的输入长度和序列哈希；默认不保存提示词、回复或工具调用内容。AISimulate 可用记录离线比较调度、路由和缓存配置，AIPerf 则在真实 GPU 上复现请求图，测量延迟、吞吐量和缓存表现。

会话调度与实测结果

调度器按会话估算每个工作节点的 KV 工作集，在工具调用边界施加背压，不中断正在生成的回复。默认利用率达到 0.95 时，它优先暂停较小的工具执行阶段会话，降至 0.80 为止；利用率回落后再按会话大小恢复。在单台 8×H100 节点上运行两个 TP4 MiniMax-M2 副本处理 SWE-bench 时，吞吐量比单独使用 KV 感知路由高约 12% 至 16%。在 8×H20-3e、Qwen3-Coder-30B-A3B-Instruct 的 Uni-Agent SWE-Bench 强化学习任务中，相比 VERL 默认 Global LB，中等并发 CC192 至 256 的模型 token 吞吐量高 11.0% 至 14.6%；完整并发测试范围内，前缀缓存命中率保持在 94.5% 以上。这些增益取决于测试负载和并发程度。

跨层缓存与后续方案

实验性的共享池索引让路由器计入 Mooncake 等外部存储中的 KV 页：只有工作节点所需的全部物理对象都存在，才算可复用；评分还会避免重复计算 GPU 本地已有的前缀。另一个已实现的 Session-Prefix Indexer 跟踪缓存块的位置、共享前缀和会话归属，为缓存策略提供依据。文章提出由 Dynamo 向 vLLM 或 SGLang 发送 KvHint，表达共享、预取、降层或保留等意图，由推理引擎按实际缓存状态执行或忽略。Share 已在 HiCache 中有工作实现，其余缓存移动策略仍在设计或实验阶段。

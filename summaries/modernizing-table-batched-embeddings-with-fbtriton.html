FBTriton 重写表批量嵌入计算

依据：原文

来源：https://pytorch.org/blog/modernizing-table-batched-embeddings-with-fbtriton/

表批量嵌入（TBE）把多张嵌入表的查找与池化合并为一次 GPU 操作，是推荐系统的重要算子。文章介绍用 FBTriton 实现前向和反向计算的方法，并报告与原有 CUDA 内核的性能比较。

前向计算

前向内核按索引读取表行，可乘以逐样本权重，再汇总为每个嵌入袋的输出。通用路径让一个程序处理多个袋并循环访问各表；FP16 和 BF16 权重使用 FP32 累加，FP32 权重使用 FP64 累加。特定的小表形状可用直方图统计索引，再通过 tl.dot 计算。当线性化范围小于 2³¹ 时，配置允许使用 int32 索引和偏移量，以减少存储占用；默认仍使用 int64。B200 上边界检查部分的速度最高为原来的 1.24 倍；融合检查默认关闭，偏移量检查仍由独立内核处理，加权、可变批次和 AMD 等配置回退到标准检查。

反向计算与负载均衡

反向计算先找出批次中访问过的每个表行，汇总所有对应输出梯度，再对该行执行一次优化器更新。索引转置后，同一行的访问形成长度不等的序列：少于 256 次访问时由单个程序完成；更长的序列默认拆成每段 256 次访问，并行累加后由第二个内核更新。短序列还按 next_pow2(D) 分桶，调整读取宽度，并在 GPU 上统计任务数量，避免每次反向计算都为读取计数而同步。对于 Blackwell 上的超大批次，设备级栅栏允许最后完成的程序在同一次内核启动中更新长序列。TLX Blackwell 路径还可使用 CLC，让程序完成当前任务后继续领取空闲任务，并通过 TMA 归约合并长序列的部分梯度。

可选预处理

精确逐行 Adagrad 可以保存前向计算的直方图供反向复用，前向和反向仍分别启动。另一条可选路径把索引转置、排序和游程编码移到前向。在一个大型 B200 配置中，前向耗时从 22.844 毫秒增至 33.252 毫秒，反向从 56.693 毫秒降至 32.931 毫秒，合计从 79.537 毫秒降至 66.183 毫秒，减少 16.8%。该路径默认关闭，当前 TorchRec 封装尚未提供入口。

测量结果与适用范围

在 GB200 上，以精确逐行 Adagrad 和 FP16 权重测试 307 个分片配置（283 种不同形状），前向相对 CUDA TBE 的加速比中位数为 1.28 倍。反向收益主要来自让长度 32 至 255 的序列继续使用简单的流式处理；在该区间较深处，Triton 处理速度达到 CUDA 的 4.3 倍。访问序列全部短于 4 次的 11 个分片仍慢于 CUDA，长度超过 256 次的形状大致持平。

实践意义

作者认为，改用 Python 编写稀疏计算路径后，调整分流阈值和读取宽度更容易；Blackwell 专有功能也可作为配置加入，而不必为 Hopper 或 AMD 另写整套内核。进一步融合前向、反向及优化器处理仍是未来方向，文章没有给出这些融合方案的实测收益。

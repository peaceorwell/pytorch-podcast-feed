PyTorch 加速器集成工作组 2026 年上半年进展

依据：原文

来源：https://pytorch.org/blog/pytorch-hardware-enablement-updates-from-the-acceleration-integration-working-group/

PyTorch 加速器集成工作组汇总了 2026 年上半年的工作：改进跨仓库持续集成、测试复用，以及 PrivateUse1 后端的性能分析、分布式训练和编译器接入路径。这些工作旨在减少硬件厂商维护补丁的负担，并让上游改动更早接受下游验证。

集成难题

新加速器需要接入设备注册、算子分派、测试和运行时等多个环节，但现有示例常与特定硬件绑定。PyTorch 上游测试也难以覆盖仓库外的后端，维护者往往要等改动合入后才发现兼容性问题。工作组因此推动可复用的接口、参考实现和验证流程。

跨仓库持续集成

Cross-Repository CI Relay（CRCR）在 PyTorch 拉取请求创建或提交推送后，向已登记的下游仓库并行发送事件；各仓库运行自己的测试，再通过经 GitHub OIDC 验证身份的回调上报结果。结果汇入 PyTorch CI HUD。L1 至 L4 四级参与机制逐步支持通知、结果展示，以及对上游请求设置非阻断或阻断检查。文章称，身份验证、许可名单、限流等措施可限制下游仓库对上游基础设施和合并决策的影响。

测试复用

PyTorch 有超过 60 万个测试用例，但设备名称、内存接口和跳过条件等硬编码曾迫使新后端维护补丁。上半年，贡献者迁移了 276 多个测试文件，使相关测试按设备参数运行；同时为测试类加入硬件分类元数据和筛选参数，供不同执行方式选取测试。项目跟踪了 259 项工作；启动时仍有 1,191 个未分类文件，暂列许可名单。按功能、类、测试和算子跳过用例的机制，可配合分类信息适应后端当前的实现范围。

PrivateUse1 参考实现与性能分析

OpenReg 是基于 CPU 的最小化参考后端，展示设备注册、算子分派、流和事件管理，并通过测试检查 PrivateUse1 集成路径。工作组还为它加入性能分析参考桩：仓库外后端可注册 IActivityProfiler，接通会话生命周期、活动类型和关联 ID，再替换为自己的设备性能分析实现。相关 torch.profiler 测试覆盖注册、会话和回退路径。OpenReg 及其分析桩都不以生产性能为目标。

分布式与编译器接入

工作组开始构建 OCCL，作为 OpenReg 的 c10d 自定义后端参考，说明 ProcessGroup 注册、集合通信分派和 Work 完成语义。编译器方面，OpenReg 示例展示后端如何接入 Dynamo 和 Inductor，验证图捕获并生成融合内核；配套指南说明两个接入路径。这些示例侧重解释接口，不提供生产级性能结果。

平台信息与后续工作

PyTorch 新增官方 Additional Platforms 页面，并从安装页链接，供用户查找其他计算平台。厂商须提交申请及文档、持续集成、安全策略等证据，经过审核才能列入。下半年，工作组计划继续减少未分类测试，扩展分布式、JIT 和自动求导测试覆盖，并将硬件分类接入持续集成调度；OpenReg 也将扩展到更多子系统。文章没有给出新后端的性能基准或量化的接入成本降幅。
